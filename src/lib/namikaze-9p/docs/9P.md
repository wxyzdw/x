# namikaze-9p

The 9P2000 protocol stack: the wire format, a server framework, a
synthetic file tree and a synchronous client, transcribed from the
surveyed Plan 9 4th edition sources (`sys/include/fcall.h`,
`sys/src/lib9p`, `sys/src/lib9p/file.c`, `/sys/src/9/port/error.h`).
Everything in this system that wants to say "everything is a file"
speaks through this crate.

## Modules

| module | provides |
| ------ | -------- |
| proto  | the 9P2000 message set as a Rust enum, Qid, Dir, open modes, limits (msize, MAX_WELEM), message type names |
| codec  | size-prefixed wire framing: one fixed-size buffer per message, string/field bounds, no allocation beyond the frame |
| error  | the `Error` taxonomy: server errno leaf (`Errno`) bound to the exact strings of `/sys/src/9/port/error.h`, wrapped in a context chain (operation, element, cause) |
| server | the connection engine: version negotiation, a fid table, the T-message dispatch, walk(5) semantics (first-element failure is Rerror; a partial walk establishes no new fid) |
| synth  | an in-memory tree in the shape of `lib9p/file.c`: directories, static files, dynamic files whose content is generated at open |
| client | `Conn`: handshake, typed rpc with strict reply validation, positioned walk errors, raw send/recv for debugging |

## Design rules

- std-only, `#![forbid(unsafe_code)]`; the wire format is parsed by
  hand against explicit bounds, so a hostile frame is data, never a
  crash: it is answered with a salvaged tag and the session survives.
- The server never panics on peer input. Every failure path is an
  `Rerror` carrying the plan9 errno wording; the errno leaf is machine
  checkable (`Errno::leaf`) while `to_string` renders the full chain.
- Errors carry their context: `Twalk: walk_path "top/nope": server:
  file does not exist` names the operation, the path and the leaf
  errno, in that order.
- Walk semantics follow `walk(5)` exactly: a failure on the first
  element is an error on the wire; a failure on a later element is a
  partial `Rwalk` and the new fid is NOT established.

## When to extend

Add a message only after reading the surveyed `fcall.h` entry for it -
the enum, the codec and the server dispatch move together. New errno
strings come from `error.h`, never from invention. The synthetic tree
grows new node kinds (name-based virtual directories, per-process
views) only when a real consumer needs them.
